# Android TV Apps Helper v0.3.1

## Native-choice enforcement

- 四平台包移除 `allowed-tools` 限制清单，继承宿主工具可用性及正常权限；WorkBuddy、豆包工作与 Claude 适配器要求兼容问题直接调用 `AskUserQuestion`。
- Codex 包在 `request_user_input` 可用时调用原生选择组件；当前模式未暴露该工具时，必须记录具体原因后才能使用文字菜单。
- 会话统一以 `--surface auto` 启动，模型不能自行选择 `text_menu`。
- Harness 为每个问题输出 `presentation.mode`、平台工具名、完整工具参数和显示标签到稳定值的映射。
- 原生工具不存在、调用失败或渲染失败时，通过 `record-surface-failure` 保存失败类型、详情和时间；待答问题保持不变。
- 每次提问生成独立实例标识；降级回调必须匹配当前问题、展示摘要和工具，旧问题或同名旧实例的回调不能影响新问题。
- Codex 严格遵守 `request_user_input` 的 2–3 选项限制；WorkBuddy、豆包工作与 Claude 的 `AskUserQuestion` 按 2–4 选项适配，不再生成宿主拒绝的参数。
- 因题型或选项数量不兼容而进行的单轮文字降级不会永久关闭后续原生组件；临时调用/渲染失败也只降级当前问题。
- 原生组件保留“推荐”标记与稳定值映射；无法在卡片内放 Markdown 表格时，先紧贴组件显示 `context_markdown`，同时在组件内保留关键阻塞和解决办法。
- 文字降级会在状态表中显示 ⚠️、明确原因和机器可读的失败代码。

## Validation boundary

- 116 项自动化测试通过，覆盖原生工具路由、选项映射、同题降级、过期回调拒绝、平台包和四平台共享 Harness。
- 最终包已替换三平台本地 Skill；Codex CLI 最终包只读预检通过，四选项问题因宿主上限使用明确提示的文字降级，并非原生 UI 通过。
- WorkBuddy、豆包工作的早期候选包实测出现原生选择组并完成安全退出；最终包 UI 复测被电脑控制服务 `native pipe startup failed` 阻塞，不能视为最终界面验收通过。豆包最终云端副本刷新未验证。
- 安装、对话、失败记录与验收边界见 [测试报告](https://github.com/HXWfromDJTU/android-tv-apps-helper/blob/v0.3.1/docs/platform-validation.md)。本轮未操作实体电视。
- Claude 继续按用户决定只做包级验证，不声明客户端验收。
